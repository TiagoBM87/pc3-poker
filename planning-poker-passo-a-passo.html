01

Modele a sala antes da interface

Toda a aplicação gira em torno de um único documento por sala. Separe o que é metadados (título, host, revelação e timer), o que são participantes e o que são votos.

src/types/poker.ts
export interface RoomMetadata {
  title: string;
  createdAt: number;
  isRevealed: boolean;
  timerEndsAt?: number | null; // timestamp absoluto do fim do timer
  hostId?: string | null;
}

export interface RoomState {
  metadata: RoomMetadata;
  participants: Record<string, Participant>;
  votes?: Record<string, VoteValue>;
}

O voto é uma string curta — '1', '13', '?', '☕' — em vez de um número. Isso simplifica o banco e permite cartas especiais.

Regra de ouro: grave os votos, mas nunca os envie para a tela de outro participante antes de isRevealed === true. A anti-trapaça real fica nas regras do banco; a interface faz a parte dela.
02

Crie o baralho e o flip 3D

O deck é uma lista fixa de valores Fibonacci. Cada valor recebe um naipe e uma cor, enquanto ? vira uma carta especial de “não sei” e ☕ a carta de pausa.

src/config/cards.ts
export const CARD_VALUES: VoteValue[] =
  ['1', '2', '3', '5', '8', '13', '21', '?', '☕'];

const SUITS = [
  { symbol: '♠', tone: 'black' },
  { symbol: '♥', tone: 'red' },
  { symbol: '♦', tone: 'red' },
  { symbol: '♣', tone: 'black' },
];

export function getCardAppearance(value: VoteValue) {
  if (value === '?') return { rank: '?', symbol: '★', tone: 'violet', label: 'Não sei' };
  if (value === '☕') return { rank: '☕', symbol: '★', tone: 'gold', label: 'Pausa' };

  const index = CARD_VALUES.indexOf(value);
  const suit = SUITS[index % SUITS.length];
  return { rank: value, symbol: suit.symbol, tone: suit.tone };
}

Para o flip, use perspective no contêiner e preserve-3d no elemento interno. O verso começa visível; a frente fica rotacionada em 180deg.

CSS essencial
.flip-card {
  position: relative;
  transform-style: preserve-3d;
  transition: transform .55s cubic-bezier(.2, .8, .2, 1);
}
.flip-card.is-flipped { transform: rotateY(180deg); }
.flip-face {
  position: absolute;
  inset: 0;
  backface-visibility: hidden;
}
.flip-back { transform: rotateY(180deg); }

O verso azul-marinho com treliça dourada é só CSS: gradientes repetidos e uma borda interna. O rosto da carta usa papel marfim, moldura dourada e tipografia serifada.

03

Assine o estado em tempo real

Um único subscribe no nó da sala alimenta o React. O hook guarda o estado bruto, mas entrega à interface uma versão sanitizada: antes da revelação, somente a lista de quem votou fica visível.

src/hooks/usePokerRoom.ts
const unsubscribe = roomService.subscribe(roomId, (nextRoom) => {
  setRoom(nextRoom);
});

const revealed = room?.metadata.isRevealed ?? false;
const rawVotes = room?.votes ?? {};
const votedUserIds = Object.keys(rawVotes);

const safeRoom = {
  ...room,
  votes: revealed ? rawVotes : undefined,
};
  • Firebase: onValue no caminho rooms/{roomId}.
  • Demo local: localStorage + BroadcastChannel para sincronizar abas.
  • Presença: ao entrar, grave o participante; ao sair, remova o participante e o voto.
Dica: exponha myVote separadamente. O usuário precisa ver a própria carta selecionada, mesmo que os votos dos outros continuem ocultos.
04

Revele e calcule o resultado

Revelar é uma escrita atômica em metadata.isRevealed. Quando o estado volta pelo subscribe, todas as cartas viram ao mesmo tempo. A média considera apenas cartas numéricas; ? e ☕ aparecem no resultado, mas não entram na conta.

src/lib/stats.ts
const values = Object.values(votes);
const numeric = values
  .filter((value) => value !== '?' && value !== '☕')
  .map(Number);

const average = numeric.length
  ? numeric.reduce((total, value) => total + value, 0) / numeric.length
  : null;

const min = numeric.length ? Math.min(...numeric) : null;
const max = numeric.length ? Math.max(...numeric) : null;

const hasConsensus =
  numeric.length === values.length &&
  numeric.length > 0 &&
  numeric.every((value) => value === numeric[0]);

A moda é a carta mais repetida. Se houver empate, mostre todas separadas por ponto médio. O confete pode ser disparado apenas quando hasConsensus for verdadeiro.

05

Adicione o timer de 30 segundos

O timer é opcional e pertence à rodada. O host grava um timestamp absoluto em metadata.timerEndsAt. Todos os clientes calculam o restante com o próprio relógio e mostram o mesmo countdown.

  1. O host clica em Timer 30s.
  2. O serviço grava timerEndsAt = Date.now() + 30_000.
  3. Um intervalo atualiza o badge e a barra de progresso.
  4. Ao chegar a zero, qualquer cliente tenta concluir o timer.
  5. Uma transação só revela se o timestamp ainda for o mesmo e a rodada não tiver sido revelada.
Contrato do serviço
startRoundTimer(roomId, endsAt): Promise<void>;
clearRoundTimer(roomId): Promise<void>;
completeRoundTimer(roomId, expectedEndsAt): Promise<void>;
Conclusão atômica (Firebase)
await runTransaction(metadataRef, (current) => {
  if (!current || current.isRevealed) return current;
  if (current.timerEndsAt !== expectedEndsAt) return current;
  if (Date.now() < expectedEndsAt) return current;

  return { ...current, isRevealed: true, timerEndsAt: null };
});
Por que transação? Todos os clientes tentam revelar ao mesmo tempo. A transação com expectedEndsAt garante que só a primeira gravação válida vence; as outras viram no-op. Revelar manualmente, cancelar ou iniciar nova rodada sempre limpa o timer.
06

Defina o host e cuide da presença

O primeiro participante a entrar vira host e recebe permissão para revelar, reiniciar e controlar o timer. Se ele sair, o participante mais antigo assume por transação.

Reatribuição do host
await runTransaction(hostRef, (currentHost) => {
  if (currentHost === null || currentHost === staleHostId) {
    return earliestParticipant.id;
  }
  return currentHost;
});
  • No Firebase, registre onDisconnect para participante e voto.
  • Ao fechar a aba, um DELETE via REST com keepalive limpa a presença na hora.
  • Links compartilhados passam por uma tela de entrada que confirma nome e papel.
  • O host não deve ser um cargo persistente no navegador: o banco é a fonte da verdade.
07

Configure o Firebase e as regras

Crie um projeto no Firebase, ative o Realtime Database e copie as credenciais para .env.local. O app usa long-polling forçado para funcionar atrás de VPNs que bloqueiam WebSockets.

.env.local
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=seu-projeto.firebaseapp.com
VITE_FIREBASE_DATABASE_URL=https://seu-projeto-default-rtdb.firebaseio.com
VITE_FIREBASE_PROJECT_ID=seu-projeto
VITE_FIREBASE_STORAGE_BUCKET=seu-projeto.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
database.rules.json — início rápido
{
  "rules": {
    "rooms": {
      "$roomId": {
        ".read": true,
        ".write": true
      }
    }
  }
}
Produção: regras abertas são só para começar. Restrinja por autenticação/App Check, valide os valores das cartas e evite permitir que alguém altere hostId ou timerEndsAt sem ser o host.
